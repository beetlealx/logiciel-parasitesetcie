P Test Dolibarr

Outil de validation de l'intégration API Dolibarr avant le démarrage du projet Claude Code.

À propos des erreurs CORS : par défaut, Dolibarr n'autorise pas les appels API depuis un navigateur sur un autre domaine. Les tests directs ci-dessous échoueront probablement avec une erreur réseau ou CORS. C'est normal et ce n'est pas un blocage — les appels API se feront depuis le serveur Next.js dans l'app finale, où CORS ne s'applique pas. Utilisez les commandes curl générées pour valider depuis votre terminal.

0Configuration

Renseignez l'URL de votre API Dolibarr et votre clé API. Ces valeurs ne sont pas envoyées ailleurs ; elles restent dans votre navigateur (session courante uniquement).

1Test connectivité (lecture)

Récupère 1 tiers de votre Dolibarr pour valider l'URL et la clé API.

2Test recherche tiers

Cherche des tiers dont le nom contient la chaîne ci-dessous (utilisée par l'autocomplétion de l'app).

3Test info utilisateur courant

Récupère l'ID de l'utilisateur Dolibarr lié à votre clé API. Cet ID est à reporter dans DOLIBARR_USER_OWNER_ID du fichier .env de l'app.

4Test création action CRM écriture réelle

Crée une action CRM de test sur un tiers existant. Ce test simule ce que fait l'app à la fin de chaque intervention.

⚠️ Attention : ce test crée une vraie ligne dans votre Dolibarr. La commande de suppression (curl DELETE) est fournie dans le résultat pour nettoyer ensuite.
